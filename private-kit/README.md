# پاسخ‌بان — بستهٔ کارِ مخزن خصوصی (این نوبت)

این پوشه بخشی از مخزن **ویترین عمومی** نیست و به آن هم push نمی‌شود؛ بستهٔ کنشی برای خودتان است:
رفع نشتی مخزن توسعه + ابزار تولید بستهٔ نصب. اگر نمی‌خواهید، همین پوشه را از درخت این مخزن هم بردارید
و فقط محتوایش را روی مخزن توسعه اعمال کنید.

| فایل | کارش |
|---|---|
| `LEAK-FIX.md` | **اول این را بخوانید.** دستور کار سه‌مرحله‌ای: مخفی‌کردن مخزن، حذف ZIPها از `main`، بازنویسی تاریخچه + شاهدهای نشتی فعلی |
| `.gitignore` | فایل آمادهٔ ریشهٔ مخزن **خصوصی** (برای مخزن ویترین عمومی، نسخهٔ جداگانه‌ای در همان مخزن هست) |
| `tools/build-release.sh` | ساخت بستهٔ نصب با پوشهٔ ریشهٔ `pasokhban/`، با بررسی یکسان‌بودن شمارهٔ نسخه در سه جا |
| `tools/preflight.sh` | خودآزمون پیش از انتشار: نسخه، کلید/توکن، ریشهٔ بسته، ZIPهای داخل گیت، تمیزی مستندات عمومی |

## طرز استفاده (روی مخزن خصوصی توسعه)

```bash
# یک‌بار: این فایل‌ها را به مخزن توسعه کپی کنید
cp tools/build-release.sh tools/preflight.sh  <repo>/tools/
cp .gitignore                                 <repo>/.gitignore   # اگر نسخهٔ بهتری ندارید

cd <repo>
bash tools/build-release.sh                 # خروجی در pasokhban-build/ (در .gitignore است)
bash tools/preflight.sh                     # باید با «همهٔ بندها پاس شد» تمام شود
bash tools/preflight.sh pasokhban-build/pasokhban.3.2.6.zip
```

هر دو اسکریپت فقط می‌خوانند و چیزی را تغییر نمی‌دهند؛ خروجی بیلد هم در `pasokhban-build/` می‌ماند
که در `.gitignore` کنار همین بسته پوشش داده شده تا دوباره داخل گیت نرود.

## چه چیزی در این بسته نیست

- هیچ `*.php`، هیچ کلاس، هیچ تکه‌کد افزونه و هیچ بستهٔ نصب — فقط دستور کار و ابزار.
- هیچ کلید، توکن یا رمزی. برای دسترسی به مخزن خصوصی از مکانیزم خود گیت‌هاب استفاده کنید،
  نه از فایل‌های کنارِ مخزن.

## وضعیت

- اسکریپت‌ها با `bash` نسخهٔ ۴ و بالاتر کار می‌کنند و به `zip`، `unzip` و `git` نیاز دارند.
- اگر تصمیم گرفتید مخزن توسعه را Private نکنید، دستور کار `LEAK-FIX.md` را انجام ندهید — ولی بدانید
  سورس محصول همان‌طور عمومی می‌مانَد و هر روز می‌تواند آرشیو و آینه شود.
